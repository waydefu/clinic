# RC-11 治理分工與每週讀回

**狀態：待負責人審閱的提案；不是新的部署或雲端授權。** 本次不修改 `GOVERNANCE.md` 或 `AGENTS.md`；以下角色分工供後續治理變更審閱，不改既有權威表或安全底線。

- 負責人：業務決定及須逐批明確同意的受保護操作。
- Claude：監督、驗收與合併；有邏輯變更先通知負責人。
- 長跑 gpt-6.1-terra：主刀實作。
- Sonnet：寫程式。
- Haiku：唯讀與實測；實測須在另行核准的範圍內。

角色分工不使代理取得部署、雲端狀態、IAM、金鑰、業務決定或 C1～C6 批次授權。合併與逐批核准的紀錄見[決定登記簿](../product/phase-1-decision-register.md)。

## 每週治理讀回清單

每次記錄日期、執行者、資料來源與證據連結；無法讀回時記 `NOT_CHECKED`，不得沿用舊結果冒充當週通過。

- [ ] 分支保護：讀回管理者是否受約束、必要檢查、強制推送限制與審查要求；與 D-013 及 RC-04 的實際讀回能力對照。RC-04 尚未完成時，不能宣稱自動化或當週狀態已驗證。
- [ ] 檢查 [`security/audit-exceptions.json`](../../security/audit-exceptions.json) 各有效例外到期日與退出條件；將即將到期或已到期項目列明，不自行延長或放寬 gate。
- [ ] 核對[決定登記簿](../product/phase-1-decision-register.md)與 [RC 計畫第二節](2026-11-08-phase1-rc-delivery-plan.md)的待決事項、負責人及期限；區分已定案與未定案。
- [ ] 讀取 [RC 計畫第九節](2026-11-08-phase1-rc-delivery-plan.md)的更新日與各包最新證據；由指定台帳負責人更新，不以清單本身代替更新或實測。

若需要變更分支保護、例外、部署或雲端狀態，另提明確範圍取得負責人核准；本清單不授權執行。

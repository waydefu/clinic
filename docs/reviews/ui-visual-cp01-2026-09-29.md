# CP-01 UI visual reference set — 2026-09-29

## Status and boundary

This is the current reference-only visual evidence set, retaken after CP-01
(`1e0b84f`, minimized booking intake) changed the Step 3 form. It was captured
from the synthetic browser-local runtime with Chromium, warm theme, `zh-TW`,
Asia/Taipei, reduced motion, DPR 1 and the same fixed application clock as the
earlier sets. It is not a cross-OS pixel gate and contains no real patient,
staff or clinic-calendar data.

The [C6 set](ui-visual-c6-2026-08-23.md) and every older dated directory remain
unchanged historical evidence. This set uses the separate
`ui-visual-cp01-2026-09-29` directory so none of them is rewritten.

## Why the capture had to change first

The capture spec had not run successfully since 2026-09-07. Three independent
drifts were found and fixed in `tests/ui-screenshots/current-ui.spec.ts`; each
was reproduced as a capture failure before the fix:

1. **Front-door split (`05470f9`, 2026-09-07).** `/` now redirects to `/clinic`
   and the workbench lives at `/staff`. The spec still opened `/`, so the theme
   reset waited on the clinic site and failed. Workbench routes now use
   `/staff` and `/staff#appointments-section`.
2. **Self-cancellation cutoff (T1-BOOK-04, 2026-09-07).** The `>20 minutes`
   rule was replaced by a same-day 10:00 cutoff. The fallback scenario still
   placed the booking 19 minutes ahead, which is now eligible, so the phone
   fallback never rendered. It now uses a booking from the previous day, the
   same technique as the patient-booking E2E spec, and both cancellation
   scenario `state` names describe the new rule.
3. **CAL-PILOT client-config probe.** Opening `/staff` fetches
   `/v1/calendar-session/client-config`; the API-less local runtime answers 404
   and the workbench deliberately falls back to synthetic mode
   (`apps/web/public/calendar-pilot-entry.js`). Chromium logs that 404 as a
   console error. The capture now allows **only** that exact message for that
   exact path, records how often it occurred as
   `consoleCounts.expectedSyntheticProbe404s`, and still fails on any other
   console error or warning. `check:structure` requires the count to be present.

`scripts/check-structure.mjs` now pins this directory, the `/staff` routes and
the renamed states.

## Manual inspection

All seventeen captures were opened and inspected on 2026-09-29. Confirmed:

- Step 3 collects name, phone, birth **month and day only** (「只需要月與日，
  不必填年份」), nationality as 本國／外國, and the optional visit notes; there
  is no national ID, passport, source channel, referrer or NHI-card-intent
  field, matching `BOOKING-MINIMIZATION-2026-09-22`;
- the lookup dialog asks for phone plus month/day and does not say which field
  mismatched;
- past the same-day 10:00 cutoff the self-cancel action is absent, the text
  reads 「預約當日 10:00 後如需取消或更改，建議直接來電診所」, the phone action is
  primary and LINE, Instagram, Messenger and Facebook are listed;
- the workbench list shows the synthetic phone, month/day and 國籍 columns
  added by `21ce6a3`; and
- no clipping, overlap or page-level horizontal overflow was observed.

Observed, not changed here: in scenarios 14 and 15 the section heading
「預約與回診管理」 shows the orange focus ring, because hash navigation moves
focus to the section heading. That is existing focus-management behaviour,
also covered by E2E, not a capture artefact.

Console errors and warnings are zero in every scenario; the only allowed entry
is the CAL-PILOT probe 404 described above (2–4 per scenario, because the
state reset also opens `/staff`).

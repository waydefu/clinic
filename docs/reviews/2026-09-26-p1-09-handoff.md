## 本機環境陷阱

- **推送憑證會過期：** 雲端代理的 git 內嵌 token 與 `gh` token 都可能中途失效。`ManagePullRequest` 以 Cursor app 身分建 PR 會因「must be a collaborator」失敗；本次改用 GitHub MCP（waydefu）建 PR、合併、必要時以 `push_files` 提交，並以匿名 fetch 逐位元組比對。
- **ADC 沒有 quota project：** Hosting、Monitoring REST 要加 `x-goog-user-project: beauessence-clinic-stg-c1a01`；Firebase CLI 要設 `GOOGLE_CLOUD_QUOTA_PROJECT=beauessence-clinic-stg-c1a01`。
- **Terraform backend：** `backend "gcs" {}` 是空的，init 要帶 `-backend-config=bucket=beauessence-clinic-stg-c1a01-tfstate -backend-config=prefix=<stack>`。Terraform 1.9.8 裝在 `/tmp/tfbin`，不在 repo。
- **`TF_VAR_*` 會殘留在 shell：** 套用後不 unset，之後跑 `terraform test` 會因 apply 開關被打開而失敗。
- **管線結束代碼：** `cmd | tail; echo $?` 取到的是 `tail` 的結束代碼；回報 gate 時要取指令本身的結束代碼。本次曾因此誤報 lint 通過。
- **Firebase Hosting `pinTag`：** 釘的是最新建立的 revision，不是正在服務的 revision。若有 0% 探測 revision，Hosting 會被釘到它。部署後務必核對 tag 指向，或用 `update-traffic --update-tags` 修正。
- **Monitoring 條件必須限制 `resource.type`：** 否則 API 回 400。Cloud Run 應用 log 是 `cloud_run_revision`。
- **限流 429 的歸因：** burst 限流先跑，擋下時不寫 Firestore；要證明持久計數，第 11 次必須落在新 process。
- **HTTP/2 標頭是小寫：** 讀 `retry-after` 要不分大小寫。
- **日曆：** 操作者帳號同時看得到正式診所日曆。只能用 `eventedit/<eid>` 開單一合成事件，不要開日曆總覽。
- **gcloud alpha 元件沒裝：** `gcloud alpha monitoring` 會卡在互動安裝提示；改用 Monitoring REST。
- **回診查詢語意：** 依 WP-B7，只有標記需要回診後才會回應，否則一律查無資料。
- **Stage F 網頁：** 預約頁在 `/booking`（不是 `/patient`）；Workbench internal-test 模式要 `/staff?internalTestBooking=1&stageFM11=1`；各動作都有確認對話框。

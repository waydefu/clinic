# 隱私權政策草案（預約平台）

## 2. 蒐集目的與資料類別

目前合成表單只在訪客自己的瀏覽器中處理：姓名、電話、出生月日（年份選填）、身分證／居留證號或護照號碼、健保卡攜帶意向、預約服務／時段／狀態、門診需求與來源標籤、特定來源下的介紹人姓名（選填）、120 字內的患者備註（選填），以及測試流程所需的本機紀錄。它不收 LineID、性別或電子郵件，也不把資料傳送到診所。

正式版是否可收上述每一欄仍待 D-001～D-003。尤其「想當日手術」等需求標籤與自由文字備註可能涉及健康或醫療資訊，介紹人姓名則涉及第三人的個人資料；法務／個資負責人必須逐項確認必要性、特定目的、法律依據、告知與保存方式，無法正當化的欄位應移除。平台不應再擴充收集病史、診斷、醫療影像、症狀、處方、LINE／Meta 對話全文或其他未核准資料。若日後確有醫療資料處理需求，必須另行完成醫療資料系統、隱私告知、權限與保存設計。

## 4. 當事人權利與不提供資料的影響

當事人可依適用法令向上述窗口請求查詢或閱覽、製給複製本、補充或更正、停止蒐集／處理／利用，或刪除個人資料。實際受理流程、身分驗證方式、例外情形與回覆時限應由診所法務／個資窗口核准並公布。

若不提供建立預約所必需的最小資料，診所可能無法以此線上平台完成預約；應提供 `電話人工預約／櫃檯` 等替代方式：`[待確認]`。

## 5. 行銷同意

行銷訊息、優惠通知、LINE 推播、電子郵件行銷與預約必要通知必須分開。行銷同意不得預先勾選，也不得作為完成預約的條件。目前合成預覽不發送簡訊或任何外部通知；未來若要啟用，須另行核准資料用途、供應商與退訂／人工補救流程。

## 6. 安全措施與事件處理

系統採 API 單一寫入邊界、最小權限、身分驗證與角色授權、輸入驗證、稽核紀錄、加密傳輸、祕密管理及事件處理程序。實際控制措施與通報／通知義務仍需依核准的資安政策、供應商合約與適用法令執行。

## 發布前核准清單

1. 填妥診所法定主體、聯絡窗口、保存期限、處理地區與供應商。
2. 由法務／個資窗口確認告知內容、權利行使流程與跨境處理安排。
3. 由資安負責人確認資料流、存取權限、稽核與事件應變流程。
4. 核准後建立不可竄改的 `privacy-vN` 文本與發布日期，並依核准的法律依據實作可舉證的告知／接受流程，才可讓正式預約頁蒐集真實資料。

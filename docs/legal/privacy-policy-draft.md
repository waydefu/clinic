## 2. 蒐集目的與資料類別

本預約平台僅處理建立、異動、取消及管理預約所必要的資料，例如姓名、電話、電子郵件（如自行提供）、預約服務／時段、預約狀態、隱私權政策同意版本與時間，以及系統安全稽核所需的技術紀錄。

平台**不應蒐集**病史、診斷、醫療影像、症狀、處方、LINE／Meta 對話全文或其他無法由預約目的正當化的自由文字。若日後確有醫療資料處理需求，必須另行完成醫療資料系統、隱私告知、權限與保存設計，不得以本預約表單擴充處理。

- 利用方式：預約安排、必要聯繫、取消／異動處理、資安防護、稽核及合法的薪資歸屬統計。

- 利用地區：`[待填：實際雲端服務資料處理地區與跨境安排]`。

## 4. 當事人權利與不提供資料的影響

當事人可依適用法令向上述窗口請求查詢或閱覽、製給複製本、補充或更正、停止蒐集／處理／利用，或刪除個人資料。實際受理流程、身分驗證方式、例外情形與回覆時限應由診所法務／個資窗口核准並公布。

若不提供建立預約所必需的最小資料，診所可能無法以此線上平台完成預約；應提供 `電話人工預約／櫃檯` 等替代方式：`[待確認]`。

## 5. 行銷同意

行銷訊息、優惠通知、LINE 推播、電子郵件行銷與預約必要通知必須分開。行銷同意不得預先勾選，也不得作為完成預約的條件。Phase 0 不導入簡訊通知。

## 6. 安全措施與事件處理

系統採 API 單一寫入邊界、最小權限、身分驗證與角色授權、輸入驗證、稽核紀錄、加密傳輸、祕密管理及事件處理程序。實際控制措施與通報／通知義務仍需依核准的資安政策、供應商合約與適用法令執行。

## 發布前核准清單

1. 填妥診所法定主體、聯絡窗口、保存期限、處理地區與供應商。
2. 由法務／個資窗口確認告知內容、權利行使流程與跨境處理安排。
3. 由資安負責人確認資料流、存取權限、稽核與事件應變流程。
4. 核准後建立不可竄改的 `privacy-vN` 文本與發布日期，才可讓預約頁收集同意。

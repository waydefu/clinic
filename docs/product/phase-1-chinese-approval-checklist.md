# Phase 1 中文核准清單（D-001～D-006、D-011）

**目前狀態：部分核准。** D-006 identity/security 已於 2026-07-28 核准；其他
未勾選項目維持 pending。本清單用於讓診所填寫並留存正式決策；填寫後，請將
核准者、日期與證據同步登錄到 `phase-1-decision-register.md`。決策核准不等於
已實作，也不能據此啟用公開網站、真實病患資料、Firebase、Google Calendar 或
任何外部通知。

## D-001｜資料控制者、隱私聯絡與權利請求

**核准責任人：** 診所負責人＋隱私／法務負責人  
**啟用前必要性：** 發布隱私政策、收集任何病患資料前。

- [ ] 確認正式個人資料控制者的法定名稱（不可自行推定為醫師或品牌名稱）。
- [ ] 指定隱私聯絡管道（電子郵件、電話或表單）與實際負責單位。
- [ ] 確認病患查詢、閱覽、更正、刪除、停止利用等權利請求的收件、驗證、處理與回覆流程。
- [ ] 確認一森渼診所名稱與地址可否／如何在隱私政策公開。
- [ ] 指定權利請求紀錄保存位置、存取權限與處理時限。

## D-002｜保存、刪除與供應商／資料區域

**核准責任人：** 隱私／法務負責人＋營運負責人  
**啟用前必要性：** 收集病患預約、取消、個管或稽核資料前。

- [ ] 分別訂定預約、取消、到診、個案管理、稽核、隱私接受紀錄的保存期限。
- [ ] 指定期滿刪除、匿名化、備份清除及法律保留例外流程。
- [ ] 列出 Firebase、Google、主機、NAS 等供應商與資料處理／儲存區域。
- [ ] 確認跨境傳輸、委外處理與資料處理協議的審查責任人。
- [ ] 確認病患提出刪除請求時，與薪資、稽核、法定保存義務衝突的人工處理流程。

## D-003｜隱私政策正式文字與發布流程

**核准責任人：** 診所負責人＋隱私／法務負責人  
**啟用前必要性：** 公開預約頁、隱私接受或正式資料收集前。

- [ ] 核准隱私政策全文、版本號與生效日。
- [ ] 確認告知目的、資料類別、利用期間／地區／對象／方式與當事人權利的文字。

## D-004｜服務、資源、可預約時段與排班例外

**核准責任人：** 診所營運負責人  
**啟用前必要性：** 任何正式時段、保留交易或 Google Calendar 投影前。

- [ ] 核准服務清單、對外名稱、營運占位區間／容量、緩衝與是否開放初診／回診。
- [x] 業主 2026-07-28 核准一筆預約可同時選多項服務。目前瀏覽器 `itemIds` 與正式 API/domain 單一 `serviceId`/`itemId` 尚未對齊；多服務不得自動相加服務分鐘，仍須明定 slot 占用、緩衝與容量。
- [x] 業主 2026-07-28 最終澄清止鼾／醫美實際療程時長到診後才形成、不寫死；預約仍須由 published schedule 取得 operational interval，完成後另記 actual timestamps。
- [ ] 核准醫師、診間、設備等資源與同一時段容量／衝突規則。
- [ ] 核准每週可預約星期與時段、最早／最晚預約範圍及顯示時區（`Asia/Taipei`）。
- [x] 業主 2026-07-28 選定週三至週五 12:00–20:00、週六 10:00–18:00；官網目前的週一至週五 11:00–20:00、週六 11:00–16:00 需另行更正。
- [ ] 核准休診、加開、教育訓練、維修等日期例外的建立人、核准人與稽核方式。
- [x] 業主 2026-07-28 核准：超出營業時間的自訂手術時段僅 administrator 可 override，理由必填；不得委派且不得繞過醫師／手術室／病患衝突。休診日／國定假日仍待另答。
- [ ] 核准櫃檯人工預約的優先權、衝突處理與人工覆核流程。
- [ ] 確認 Firestore 為時段權威來源；Google Calendar 僅為非同步投影，不作為鎖定依據。

## D-005｜取消、改期、爽約與費用

**核准責任人：** 營運負責人＋法務負責人  
**啟用前必要性：** 病患或人員取消／改期、爽約處理或任何費用規則前。

- [ ] 逐項服務核准取消／改期期限與系統計算方式。
- [ ] 核准病患自行取消、改期的身分驗證、步驟與畫面文案。
- [ ] 核准期限後取消的處理方式與人工例外流程。
- [ ] 核准櫃檯／主管代為取消、改期的角色、必填理由代碼與稽核內容。
- [ ] 定義爽約、標記權限、後續限制或人工處理。
- [ ] 確認訂金、費用、退款或本階段不處理的結論與法務依據。

## D-006｜身分驗證、角色與寫入權限

**決策狀態：已核准；尚未實作或驗證。**

**核准責任人：** 診所負責人＋資安負責人  
**啟用前必要性：** 任何真實寫入 API、員工登入、患者登入或權限管理前。

- [x] 核准 staff：Google federated sign-in＋診所自管帳號；Phase 1 staff role 為 administrator、front desk、physician，未明示 action 預設拒絕。
- [ ] 患者登入／本人驗證仍依 D-001～D-003、D-011；個管／薪資／臨床／財務角色另依 D-007、D-008、D-014、D-015，不從 D-006 自動推定。
- [x] 核准全體員工 MFA、自管帳號 TOTP、閒置 30 分鐘、登入絕對上限 8 小時；帳號停用完成後下一個 protected request 必須拒絕。
- [x] 核准櫃檯與管理者可完成到診；醫師與未列角色不自動取得該 action。
- [ ] 取消／改期／爽約仍依 D-005；指派個管與薪資仍依 D-007／D-008。
- [ ] 指定誰可設定「是否需要回診」與回診目標日期；系統不得自行作臨床判斷。
- [x] 確認所有正式寫入經 API 驗證、授權、欄位驗證、冪等與 audit；前端不得直接寫入 Firestore。
- [x] 核准管理者可刪除符合限定理由的預約；audit 永久、append-only，任何角色都不能修改或刪除。
- [x] 核准管理者可用多組授權碼委派櫃檯刪預約；授權碼只存安全 KDF 結果、可個別撤銷、不回顯並限制錯誤嘗試。

> D-006 的 provider、session、撤銷與委派原則已核准。精確 rate-limit 數值、
> recovery／重新綁定與 cloud 配置是

> 的技術審查項；未核准前 fail closed，不自行加入 break-glass。

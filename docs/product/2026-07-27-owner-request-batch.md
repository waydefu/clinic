## 初診基本資料表（業主 2026-07-27 提供，20260514 版）

「幫他填入病例再列印」= 用線上填的資料，**預先填好這張紙本表最上面那個大框**再列印。
其餘區塊（自主健康評量、鼻咽喉困擾、曾經治療紀錄）仍由患者到診手寫。

大框的欄位（依紙本順序）：

| 區 | 欄位 |
| --- | --- |
| 表頭 | 病歷號碼、初診日期、管理師 |
| 第一列 | 姓名、生日（年／月／日）、年齡、性別（男／女） |
| 第二列 | 身分證字號、手機、市話、婚姻（已婚／單身） |
| 第三列 | 住址、職業 |
| 第四列 | 聯絡人、聯絡人手機、關係、LineID |
| 第五列 | 如何得知診所訊息：網路搜尋／官網／IG／FB／論壇／Threads／路過／親友介紹（＋介紹人）／員工介紹（＋介紹人）／其他 |

**這解開了三個原本模糊的需求**：

- 「加上親友介紹」＝第五列「如何得知診所訊息」的其中一個選項，且要能填**介紹人姓名**。
- 「病例號碼格」＝表頭的**病歷號碼**。
- 「和工作臺一樣可複選」＝第五列是複選清單，就像工作臺既有的標籤選擇器。

**未解的一個張力**：紙本有「生日（年）」與由它推算的「年齡」。業主同時要求年份可不填——
年份留白時，**年齡欄一併留白**由櫃台到診時補，不由系統推估。

**需要決定的分界**：紙本大框有 15 個欄位，其中住址、職業、婚姻、市話、聯絡人、LineID
都是目前線上沒有收的。全部搬上線會與「個資收集低調一些」和資料最小化衝突。規劃預設
只在線上收「報到當下真的需要、且患者願意先填」的部分，其餘留白由櫃台填寫（見下一節）。

### 需要確認的一個判讀

「若患者帳戶已確認可回診，回診只能改期或取消，初診鍵禁用」有兩種讀法，實作差很多：

- **讀法 A（規劃採用）**：醫師已登錄回診指示（`latestFollowUp()` 有值）→ 初診鍵禁用並
  說明原因；患者只能走回診。
- **讀法 B**：患者**已經訂到**回診時段 → 步驟一改成顯示那筆預約，只給「改期／取消」。

兩者其實可以並存，且系統已有對應狀態（`latestFollowUp()`、`ensureWithinActiveBookingLimit`）。
規劃按「A 為主、B 併做」處理；若業主只要其中一種，動工前告知。

### P6 的合規界線

業主要的是「不要把打電話刪資料寫得太突出」。**視覺低調可以做**，但個資法第 8 條要求
蒐集前告知「當事人得行使之權利**及方式**」，第 3 條的刪除權不能拿掉。規劃的做法是：
勾選旁的連結一鍵展開**完整告知**（含權利與行使方式），符合「蒐集前告知」；只是不再用
高亮區塊呈現。**風險由資料控制者（診所）承擔**，這一點要寫進決策紀錄。

業主提供的參考條款是 AlleyPin 的文件（含該公司名稱、電話與信箱）——**只能當結構參考，
不得整份沿用**。

### P10／P11 對 domain 的影響

兩者都會改到 `packages/domain/src/patient-identity.ts`（不是只改瀏覽器端）：

- 目前 `NATIONAL_ID_PATTERN` 必填、`CALENDAR_DATE_PATTERN` 要求完整 `YYYY-MM-DD`。
- `patientIdentityKey()` 是「有身分證用身分證，否則用 `phone|birthDate`」。年份變選填 ＋
  身分證可用護照替代，會讓**後備鍵變弱**——同一支電話的家人較易被視為同一人。
- 因此規劃：識別碼欄位改為「身分證／居留證／護照擇一」，`identityKey` 優先序改為
  身分證 → 護照 → `phone|生日(含年才用)`，並在無年份時**不合併**不同人。
- 流程：改 `packages/domain` → `pnpm --filter @beauessence/domain build` → `pnpm sync:domain`
  → 連 `vendor/domain/` 與 `manifest.json` 一起提交，否則 `check:sync` 會紅。

### P5 是本批最高風險的一項

目前整份合成資料錨定在固定日期：`SYNTHETIC_WINDOW_START = '2030-01-01'`、21 天。
改成「當日起一個月」會讓時段隨今天浮動，而**既有測試大量寫死 2030 日期**——
`apps/web/src/test-only-modules.test.ts` 就有約 20 處硬編碼的 `slot_20300102_*` 之類 id。

建議做法：保留「錨點 ＋ 天數」的產生方式，但錨點改為「今天」、天數改 30，並把受影響的
單元測試改為**以凍結時鐘計算相對日期**，而不是逐一改字串。這一項單獨成一批，不與介面
調整混在同一個 commit。

### 線上收哪些、櫃台補哪些（W7 的歷史規劃；交付結果優先）

原則：**線上只收「患者自己最清楚、且預約當下就需要」的欄位**；其餘留白，由櫃台在
到診時按紙本補齊。這同時滿足資料最小化與業主「個資低調一些」的要求。

| 紙本欄位 | 線上收？ | 理由 |
| --- | --- | --- |
| 姓名、手機 | ✅ 已收 | 預約與聯絡的必要欄位 |
| 生日（月／日必填、年選填） | ✅ 已收，改格式 | D-b |
| 身分證字號／護照 | ✅ 已收，改為擇一 | P10 |
| 如何得知診所訊息（＋介紹人） | ✅ 新增 | 業主明確要求；複選 |
| LineID | ❌ 未實作 | 原規劃曾提議選填，但不在執行單；目前明確不收，改動須先過 D-001～D-003 |
| 性別 | ❌ 未實作 | 原規劃曾提議選填，但不在執行單；目前明確不收，改動須先過 D-001～D-003 |
| 病歷號碼 | ❌ 櫃台填 | **診所自己的流水號**，見下方註記 |
| 初診日期、管理師 | ❌ 系統／櫃台 | 初診日期由預約時段推出；管理師是內部指派 |
| 年齡 | ❌ 不收 | 由生日推算；年份留白時一併留白 |
| 市話、住址、職業、婚姻 | ❌ 櫃台填 | 與「預約」無關，屬到診後的病歷資料；線上收會與資料最小化衝突 |
| 聯絡人／其手機／關係 | ❌ 櫃台填 | 同上，且涉及**第三人**個資，線上代收要另有告知依據 |

**聯絡人欄位特別註記**：那是患者以外第三人的姓名與電話。由患者線上代填，等於在沒有
向該第三人告知的情況下蒐集其個資。留給櫃台當面填寫較安全，這一點要寫進決策紀錄。

**病歷號碼特別註記（2026-07-27 與負責人確認）**：它是**診所自己編的流水號**——

- **不是**健保署核發的。健保署發的是醫事機構代碼與健保卡卡號，識別病人用身分證字號，
  三者都不是病歷號。醫療法與施行細則只規定病歷要記什麼、保存多久（至少 7 年），
  **沒有規定編號方式**，所以編碼規則由各院所自訂。
- **也不是**健保卡上的卡號或身分證字號。曾經考慮過這兩種可能，都不是。

實作上的意義：因為是診所自編，這個欄位就是單純的文字輸入，**沒有格式可驗證、也不該
自作聰明去驗**；而且它不是從健保卡抄來的敏感識別碼，所以不需要比照身分證做遮罩。
若診所日後改為由本系統給號，那是另一個決定（會牽涉到號碼唯一性與跨系統對照），
不在本批範圍。

### 列印頁的做法

- 新增 `/print/intake`（或工作臺內的列印檢視），版面依紙本大框排列，A4、單頁。
- 只用 CSS `@media print`，不引入任何列印函式庫。
- 未填欄位輸出**空白底線**，讓櫃台或患者手寫，不要印「未填」。
- 頁面只在合成工作臺的測試登入 gate 後可達，並比照既有規則遮罩身分證（畫面
  遮罩、**合成列印時完整**）。這只記錄業主指定的測試版面，不代表正式紙本必須
  收完整號碼或測試登入已構成授權；必要性、列印與銷毀仍待 D-002，權限須依
  已核准但尚未實作的 D-006 server-side boundary 驗證。
- 不儲存任何病歷內容：這是一張**把已有資料排版印出**的頁面，不是電子病歷。

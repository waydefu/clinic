# Phase 1 預約營運與權限核准包

**狀態：待核准。** 本文件只整理決策，不會開放預約端點、建立 Firebase
專案、串接日曆或接收真實病患資料。

**使用方式：** 診所營運負責人、診所負責人與資安負責人填妥下列欄位，並將
核准紀錄寫入 `docs/product/phase-1-decision-register.md`。若任一必要欄位未定，
相應的 D-004、D-005 或 D-006 必須維持 `pending`。

本文件所用的技術邊界，請先閱讀
[`../architecture/domain-boundaries.md`](../architecture/domain-boundaries.md)
與 [`../architecture/api-v1-contract.md`](../architecture/api-v1-contract.md)。

### 共通資安要求

1. 所有 staff 寫入均經 API；瀏覽器、App、LINE、Meta 與 NAS 不得直接寫入
   Firestore。
2. 每個寫入請求都需要驗證、授權、欄位驗證、冪等性與稽核。
3. 帳號建立、權限提升、停權、離職與緊急復原要有責任人與留存紀錄。
4. 實際可用的登入方式、MFA、session 時限與 service account 範圍，需由
   D-006 一併核准，不能由程式自行推定。

## 核准後的開發門檻

Stage 0 的本機合成預約交易與權限測試已完成，不能把這份核准包寫成它們的
前置條件。更新決策登錄後，應先對齊 contracts/domain/policies 並補核准值測試；
D-006 與 D-010 都核准後才可準備 Stage 2 routed cloud-staging 工作。隱私
D-001～D-003 仍未核准時，任何測試都不能改用真實資料，也不能啟用公開預約端點。

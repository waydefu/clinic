# 網頁設計、動效與美學評分研究（2026-10-12）

**性質：** 研究整理，供 `.claude/skills` 的設計技能與 `scripts/design-score/` 使用；不是政策或部署授權。
**緣由：** 業主 2026-10-12 要求研究專業創作者的做法（網頁設計、動效、視覺效果、美感），據此優化技能，
並以程式為網站評分，且先不沿用舊規則評美術（決策登記簿 2026-10-12 條目）。
**方法：** 兩名研究代理共查 80 次搜尋、讀 193 個網頁（官方規格、評審頁、同儕審查論文優先），
再由兩名整理代理逐條附出處。實務者意見信心最高只標「中」，同儕審查或官方規格才標「高」。
未取得的來源列在最後一節，沒有用推測補齊。

## 1. 得獎網站怎麼被評

- **Awwwards 權重**：設計 40%、好用度 30%、創意 20%、內容 10%。至少 18 位評審，去掉離平均最遠的 3 個分數。
  榮譽提名門檻 6.5；每日最佳（SOTD）沒有公開門檻，抽樣的 SOTD 評審分數落在 7.11～7.52。
  目標因此是「每一項都不弱（各 ≥ 7.2）」，不是單項驚豔。〔高〕
  <https://www.awwwards.com/about-evaluation/>、<https://www.awwwards.com/sites/heva-health>
- **開發者評分**分六項：語意／SEO、動畫、無障礙、效能、響應式、標記。三個得獎案例中**無障礙都是最低分**
  （6.40～7.20），效能與響應式最高。本專案的嚴格無障礙與小預算是加分，不是限制。〔高〕
- **手機另外評**（Mobile Excellence 需 ≥ 75/100）；實務評審表示手機版壞掉會把網站壓在榮譽提名以下。〔中〕
- **醫療類很少拿到最高獎**：Awwwards 診所類第一頁 31 站只有榮譽提名；健康類的 SOTD 只有 HEVA Health。
  合理的第一個里程碑是榮譽提名水準。〔中〕 <https://www.awwwards.com/websites/clinic/>
- 實務評審的觀察：一個貫穿全站的核心概念、一致的字體系統、克制的配色、真實的文案與圖片、專門的打磨期；
  為了創意犧牲好用度的網站約 6.2 分；漂亮外殼配空洞文案「看起來像模板」。〔中〕
  <https://www.hontran.dev/blog/how-to-win-an-awwwards-site-of-the-day>

## 2. 第一印象與「好看」的證據

- 視覺吸引力的判斷在約 **50 毫秒**內形成，與長時間觀看的評分一致，並透過月暈效應影響對可信度與好用度的判斷
  （Lindgaard et al. 2006）。首屏的字、色、留白與照片必須在第一次繪製就到位，不靠腳本。〔高〕
- **簡單＋熟悉最好看**：Reinecke et al. (CHI 2013，450 站、548 人、500 毫秒曝光) 中，視覺複雜度是影響吸引力
  最大的因素，高複雜度大幅扣分，低與中複雜度差不多；色彩多寡影響很小。Google 的研究摘要補充：最吸引人的網站
  既簡單又符合該類網站的典型樣貌。45 歲以上對低複雜度偏好更強。〔高〕
  <https://kgajos.seas.harvard.edu/papers/reinecke13aesthetics.pdf>、
  <https://research.google/blog/users-love-simple-and-familiar-designs-why-websites-need-to-make-a-great-first-impression/>
- **美感的四個面向**（VisAWI，Moshagen & Thielsch 2010）：簡潔、多樣、色彩、工藝。區分「得獎」與「整齊」的是
  工藝——各設計維度整合得是否純熟一致。可用 4 題短版在每輪設計後問業主與幾位使用者。〔高〕
- **可信度分階段決定**：外觀決定會不會被拒絕，可信的資訊與具名的人決定會不會被選擇（Sillence et al. 2004）。
  史丹佛網站可信度十條（真實機構、專業、真人、易聯絡、專業外觀、好用、更新日期、節制宣傳、零錯誤）可當上線前
  檢核表。〔中〕 <https://credibility.stanford.edu/guidelines/index.html>

## 3. 專業工作流程

1. **先定一個核心概念**，讓它反覆出現在字、線、動效與圖片。本診所的自然概念是「呼吸與氣流」，以克制方式表現
   （例如一條細線母題、緩慢的節奏、用功能而非疾病命名：聞、呼吸、睡）。日本耳鼻喉科 Koba Clinic 的首屏就以
   「聽、聞、說、吃」框住日常功能。〔中〕 <https://koba-clinic.jp/>
2. **風格樣板先於版面**：情緒板 → 風格樣板（字體、色票、元素樣本、三個形容詞）或元素拼貼 → 字體與色彩系統 →
   用真實內容排頁面。提出兩三個具名方向讓業主選，避免各取一塊的拼湊稿。〔中〕
   <https://alistapart.com/article/style-tiles-and-how-they-work/>
3. **先灰階做層次**：用大小、字重、對比、間距建立層次，再上色；先給太多留白再收；先用間距或底色分組，
   少用框線；陰影、圖示、微互動放到最後，但一定要留打磨時間。〔中〕 <https://www.refactoringui.com/>
4. **token 先行**：色彩、字級、間距、圓角、陰影、動效先定成 `:root` 變數，元件只用 token；每輪同時看首頁、一位醫師、
   一個療程頁。〔中〕 <https://bradfrost.com/blog/post/atomic-web-design/>
5. **結構化評論**：每則意見對應目標，優缺點並陳，記錄行動項。單人設計＋業主時，用目標與 VisAWI 四面向寫成檢核表。〔中〕

## 4. 視覺系統的具體值

### 字體與繁體中文排版

- **流體字級**（Utopia 方法）：在兩個視窗寬度間插值，手機比例較小。建議基準 17→19px、比例 1.2→1.25、
  視窗 360→1240px；寫成 `clamp(最小, 截距 + 斜率·vw, 最大)`，含 rem 讓使用者縮放有效。〔中〕
  <https://utopia.fyi/blog/designing-with-fluid-type-scales/>
- **字級下限**：內文與介面 16px，14px 只給頁尾或次要文字（日本數位廳設計系統；NHS 內文桌機 19px）。〔中〕
- **每行字數**：中文長文 17～40 字，最多 48（W3C clreq）；WCAG 1.4.8 對 CJK 為 40。寬度用 **em** 設，不用 ch
  （ch 量的是窄的「0」，會讓中文多一倍）。建議長文 `max-inline-size: 34em～36em`。〔高〕 <https://www.w3.org/TR/clreq/>
- **行高**：中文需要比拉丁文寬，行距為字級的 50%～100%（行高 1.5～2.0）；建議內文 1.75、h1 1.3、h2 1.4。
  字距：內文 +0.02em，不超過 +0.05em；大標題 0。必須通過 WCAG 1.4.12 文字間距覆寫測試。〔高〕
- **系統字體堆疊**（不載入 webfont）：`'PingFang TC', 'Microsoft JhengHei', 'Noto Sans TC', 'Noto Sans CJK TC',
  'Heiti TC', sans-serif`；`lang="zh-Hant-TW"`，但字形選擇要靠明確的字體清單，不能只靠 lang。內文避免襯線系統字。〔中〕
- **字重**：只依賴 400 與 700（Windows 微軟正黑體不保證中間字重）；hover 或選取不改字重（會造成版面位移）。〔中〕
- **換行**：標題 `text-wrap: balance`、段落 `text-wrap: pretty`；兩者對中文的行為未有官方說明，必須實測；
  最後兩到四字可用 class 加 `white-space: nowrap` 保護。不要對中文用 `word-break: keep-all`。〔高〕
- **標點與強調**：引號用「」『』；刪節號與破折號各佔兩字寬且不可斷開；強調用字重或顏色，不用斜體；
  不要左右齊行或置中長文；中英之間不要手打空格（`text-autospace` 會自動加）。〔中〕

### 色彩

- 用 **OKLCH** 定 token（感知均勻），固定色相、只調亮度與彩度；以相對色語法推導 hover 等狀態。〔高〕
  <https://evilmartians.com/chronicles/oklch-in-css-why-quit-rgb-hsl>
- 每個色族 12 階語意刻度（背景、元件、框線、實色、文字）；**帶暖調的中性色**取代純灰；不超過 3 個色族；
  顏色不單獨承載意義。〔中〕 <https://www.radix-ui.com/colors/docs/palette-composition/understanding-the-scale>
- 得獎的健康網站多用**暖白底＋一個深沉的主色**：HEVA #fdfdf1／#39442b、Function #FEF9EF／#C07858、
  Royal Clinic #F3F1EF／#2D1D12，而不是冷白配飽和藍。〔低，描述性〕
- 對比目標高於最低標準：內文 ≥ 7:1、次要文字 ≥ 4.5:1、焦點框兩側 ≥ 3:1，並在強制色彩模式下仍可見。〔高〕

### 版面、圖片與細節

- **留白有意義**（品質、平靜、克制），但要有系統：所有間距出自同一組刻度，組內比組間近，內容不撐滿螢幕。〔中〕
- **編輯式網格**：12 欄、偏一側的窄文字欄、偶爾出血的圖片；不對稱要建立在嚴格網格上。〔低〕
- **圖片**：用 `<picture>` 依斷點換裁切，每張圖預留尺寸；真人真空間、單一方向的自然光、色調與配色一致；
  不在雜亂照片上直接壓字；淺色底上的圖可加 1px 半透明描邊。〔高／低〕
- **深度**：全站單一光源；陰影多層、低透明度、帶背景色相，最多兩層高度；用細線代替粗框。〔中〕
  <https://www.joshwcomeau.com/css/designing-shadows/>
- **打磨細節**：同心圓角（外 = 內 + 內距）、圖示側的光學對齊、門診時間與電話用 `tabular-nums`、hover 不改版面、
  循環動畫離開畫面就暫停。〔中〕 <https://interfaces.rauno.me/>

## 5. 動效

- **時長依互動類型**：回饋 100～150ms；小型展開 125～200ms；面板／對話框 250～300ms；大範圍移動或換頁
  ≤ 450ms；超過 500ms 就像在拖。離場約為進場的 65%～85%。（NN/g、Carbon、Material 3 三方一致）〔中〕
  <https://www.nngroup.com/articles/animation-duration/>
- **緩動 token**（Material 3 原始值）：進場 `cubic-bezier(0.05, 0.7, 0.1, 1)`、離場 `cubic-bezier(0.3, 0, 0.8, 0.15)`、
  一般 `cubic-bezier(0.2, 0, 0, 1)`；不用 CSS 內建的 ease 系列（太弱）與 linear（UI 移動）。〔中〕
  <https://raw.githubusercontent.com/material-components/material-web/main/tokens/versions/v0_192/_md-sys-motion.scss>
- **頻率決定要不要動**：鍵盤觸發與一天見很多次的動作不動畫；每頁約一個招牌時刻；任何輸入 100ms 內要有回饋。〔中〕
  <https://emilkowal.ski/ui/you-dont-need-animations>
- **只動 transform 與 opacity**，明列屬性，不用 `transition: all`；`will-change` 只給即將移動的元素。〔高〕
  <https://web.dev/articles/stick-to-compositor-only-properties-and-manage-layer-count>
- **可中斷**：狀態型 UI 用 transition（可中途改向），不用 keyframes；不要從 `scale(0)` 開始（從 0.93～0.97）；
  `transform-origin` 放在觸發點。〔中〕 <https://emilkowal.ski/ui/7-practical-animation-tips>
- **彈簧不用函式庫**：以（時長、彈性）參數化，預先取樣成 CSS `linear()`；醫療網站彈性用 0。〔高〕
  <https://developer.apple.com/documentation/swiftui/spring.md>
- **錯開**：每步 30～50ms、整段 ≤ 500ms、最多 5 項、第一項不延遲。〔低，經驗值〕
- **捲動驅動與換頁轉場**只當漸進增強：`@supports (animation-timeline: view())` 加
  `@media (prefers-reduced-motion: no-preference)`；跨文件 view transition 同源才有效，Firefox 尚不支援。〔高〕
- **對話框與 popover** 用 `@starting-style` ＋ `transition-behavior: allow-discrete`，不需 JS。〔高〕
- **減少動態**：移除位移、縮放、視差，保留透明度變化；預設寫靜態終態，動效放進 `no-preference` 區塊。〔高〕
- **高級 vs 花俏**：高級是快、有目的、空間一致、可中斷、少見；花俏是長、循環、自動播放、裝飾、劫持捲動。〔中〕

## 6. 視覺效果

- 毛玻璃（`backdrop-filter`）最多用在一兩個固定表面，要有不透明的退路與 `prefers-reduced-transparency` 版本。〔中〕
- 顆粒雜訊只用靜態、同源的小磚、極低透明度去掩蓋漸層色帶；不要動畫化 `feTurbulence`。〔中〕
- 不要自訂游標或游標跟隨；只在精確指標裝置、不隱藏原生游標時才考慮，減少動態時關閉。〔低〕

## 7. 醫療院所網站的模式

- **以就診任務組織**：找醫師、了解問題、知道看診流程、預約或來電；預約入口在 header、首屏、頁尾都出現；
  用「你」直接說話。〔中〕（NHS、Samsung Medical Center 英文站獲 2026 Red Dot）
- **降低初診焦慮靠說明，不靠裝飾**：看診流程、檢查內容、醫師的作法、門診時間與交通放前面。〔中〕
- **醫師要具名、有資歷時間軸**，清單頁與個人頁同一格式（醫療法第 85 條允許刊登醫師學經歷與證書字號）。〔中〕
- **療程頁寫成衛教**：病況、作法、何時該看醫師、看診內容、風險；不寫成功率、不放前後對比、見證、排名或保證。
  動效與圖片同樣不能暗示療效（不做數字跳動、前後對比滑桿、「呼吸變順」動畫）。法條解讀需診所法律確認。〔高〕
  <https://law.moj.gov.tw/LawClass/LawAll.aspx?pcode=L0020021>
- 範例：Koba Clinic（耳鼻喉，日本）、HEVA Health（Awwwards SOTD）、Royal Clinic、Function Health、NHS.uk、
  Samsung Medical Center、Sant Joan de Déu。借語氣、配色邏輯與結構，不借見證、前後對比與統計宣稱。

## 8. 程式化美學評分

### 可用的指標（實作在 `scripts/design-score/`）

| 指標 | 定義 | 證據 |
| --- | --- | --- |
| 色彩豐富度 | Hasler–Süsstrunk：√(σrg²＋σyb²)＋0.3·√(μrg²＋μyb²) | 網站上與感知色彩 r = .71（Reinecke 2013） |
| 視覺複雜度 | 文字面積、非文字面積、文字群組數、圖片數、版面葉節點 | 回歸 R² = .65（Reinecke 2013），複雜度主導吸引力 |
| 邊緣密度 | Sobel 邊緣像素比例（固定門檻） | 與雜亂度評分 r = .83（Rosenholtz 2007） |
| 壓縮位元率 | 固定品質 JPEG 的 bits/pixel | 網頁上偏弱（Bakaev 2019 adj R² = .115），只當警報 |
| 留白比例 | 1 − 內容矩形聯集 / 視窗 | 與主觀留白 τ = .635（Bakaev 2019） |
| Ngo 密度／平衡 | 覆蓋率 50% 最佳；左右上下視覺重量差 | 平衡與美感相關，等量中心無鑑別力 |
| 對齊線 | 物件左右緣相異位置數 | Bakaev 2019 聯合模型中最強的複雜度預測項 |
| 主要行動顯著度 | Spectral residual 顯著性在 CTA 內的集中程度；注意力熵 | 熵與美感 r = −.65（Gu 2018，眼動），預測圖未驗證 |
| 每行字數、行高、字級比例一致性 | DOM 量測 | clreq、WCAG 1.4.8／1.4.12 |
| 動效合規 | 只動合成屬性、UI ≤ 450ms、進場淡入 ≤ 600ms、不無限循環 | web.dev、NN/g、Vercel 規則 |

### 使用紀律

1. **只當相對比較與退步警報**：最好的模型只解釋約一半的人類評分變異（Reinecke 48%；Bakaev 調整 R² .552），
   不是得獎預測。不要只優化單一指標（Goodhart）。
2. **參考分布用得獎語料**，以得獎 vs 一般網站的 AUC 驗證；得獎網站自己計分時用留一法。
3. **無障礙是硬性關卡，獨立在分數外**：高評分網站反而常有較多無障礙錯誤（Ivory & Hearst 2002）。
4. **量測要可重現**：固定視窗、DPR、字體環境，截圖前停用動畫；跨作業系統的數字不能比較。
5. **人的評分才是最終標準**：500 毫秒曝光、9 分量表（Reinecke 協定），或 VisAWI 四題短版。

### 2026-10-12 首次驗證結果

- **語料**：31 個網站（Awwwards 健康／診所類 2023 年起的榮譽提名或每日最佳 10 個、只有提名 8 個、一般台灣診所
  11 個、本專案 2 個版本）。逐一檢視首屏後排除 5 個（網域停放、只剩搬家通知、防火牆擋下 2 個、首頁輪播未載出），
  另有 4 個桌機量測逾時；實際用於驗證的是得獎 7 個、一般 10 個。
- **研究先驗權重的綜合分數沒有通過**：AUC 0.23，方向相反——一般台灣診所網站反而得分較高。文獻的「越簡單、
  越平衡越好」在這批得獎健康網站上不成立：它們圖大、字大、不對稱，物件少而大，注意力集中，細碎紋理少。
- **改用擬合模型**：22 項指標事先全部列入、L2 羅吉斯迴歸，留一法 AUC 0.757。單項區分力最強的是手機與桌機的
  「對齊線／物件」（得獎較高，0.91／0.80；反映物件少而大）、桌機首屏壓縮複雜度（得獎較低，0.19）、桌機首屏
  平衡（得獎較不平衡，0.16）與首屏注意力分散度（得獎較集中，0.24）。

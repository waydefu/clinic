# 合成測試版工作臺與病患預約 UI／UX

## 適用範圍

本文件規範 `apps/web/public` 的非正式測試版。它可在本機雙重開關下運行，也可發布到已記錄的 Firebase Hosting preview channel。所有狀態僅存在記憶體或目前瀏覽器的 `localStorage`，不是正式診所後臺、病患入口、登入系統或資料庫。

D-001～D-011 尚未核准的政策、角色與文字均使用清楚標示的合成自訂值；禁止因此推定診所已核准正式規則。

## 角色與最小權限

| 視角 | 可使用功能 | 不可使用功能 |
| --- | --- | --- |
| 管理者（模擬） | 多日多時段排班、刪除時段、加開／休診、回診決定、帳號建立／停用／恢復、患者公告、維護模式、發布紀錄 | 真實登入、正式授權、真實資料與外部整合 |
| 櫃台員工（模擬） | 查看排班、建立／取消預約、完成到診、查看非金額個管工作量 | 排班與例外設定、回診決定、帳號治理、公告與維護設定 |
| 病患（合成） | 選擇初次諮詢或已授權回診、選時段、確認、建立與取消合成預約 | 輸入姓名、電話、Email、病情、醫囑、付款或其他真實資料 |

目前的角色選單只用於 UX 與最小權限驗證，不是 Authentication。正式版必須由後端驗證身分與角色，不能只依賴前端隱藏控制項。

## 工作臺功能契約

1. 每週排班可一次選取多個星期，並為每批星期加入相同的起訖時間。
2. 同一天可重複加入多段互不重疊時段；重疊、結束早於開始與未選星期必須拒絕。
3. 管理者可逐筆刪除每週時段與日期例外；`closed` 休診優先於 `extra_open` 加開。
4. 日常預約卡必須明確區分可預約、已預約、取消處理中與已完成，並依狀態停用不合法動作。
5. 回診只能呈現授權人員的明確決定；系統與 AI 不得自行做臨床判斷。
6. 個管工作量只顯示合成個管 ID、月份、不重複患者數與規則版本，不計算或顯示薪資。
7. 帳號管理只建立合成標籤與角色；至少保留一個啟用中的管理者。
8. 患者公告只在 `published` 時顯示；維護模式啟用後，患者預約流程必須完全隱藏。
9. 發布紀錄只代表目前瀏覽器中的合成操作紀錄，不會觸發 Firebase 或正式環境部署。

## 病患端企業級流程

病患頁使用四個可返回修改的步驟：

1. 選擇「初次諮詢」或「回診預約」。回診尚未經授權確認時不可進入選時段。
2. 以 `Asia/Taipei` 顯示日期、開始時間、結束時間與預估分鐘數。
3. 顯示完整預約摘要與固定 `patient_test_001` 合成身份；使用者確認不會輸入真實資料後才可送出。
4. 顯示預約編號與目前狀態；若取消同一筆預約，完成卡與下方預約卡必須同步改成「取消處理中」。

頁首提供主導覽、環境徽章與患者公告；頁尾重申公開預覽與無真實資料界線。桌面、平板與 390px 手機寬度不得水平溢出，互動控制需保留清楚的鍵盤焦點樣式。

## 安全與可維護性規則

- 動態顯示只允許不透明合成 ID、狀態、測試時間、合成政策／服務參照及彙總數字。
- 自訂公告、維護說明、帳號標籤與發布摘要不得輸入患者、員工、憑證或其他真實敏感資料。
- 不載入外部字型、追蹤碼、遠端圖片或第三方 UI 資產。
- `index.html`／`patient.html`／`admin-shell.html` 負責語意結構，`styles.css` 與 `admin-v2.css` 集中設計 token 與元件樣式，`admin-bootstrap.js`／`patient-app-v2.js` 只處理互動與渲染，`staging-store-v2.js` 與 `modules/` 集中合成狀態轉換。
- 正式 API、行動 App 與 NAS 必須共用 domain API；不得讓任何客戶端直接寫 Firestore。

## 回歸驗證

每次變更至少執行：

```powershell
corepack pnpm check:ui
corepack pnpm verify
```

`verify` 已包含 `check:format`（Prettier），排版不再由人工維持。

實機瀏覽器需覆蓋：管理者／櫃台切換、批次新增與逐筆刪除、多種日期例外、帳號生命週期、公告、維護啟閉、病患四步驟預約、取消狀態同步、桌面與 390px 手機版，以及 0 console errors／warnings。

2026-07-21 起，實際載入的管理工作臺改由 `admin-bootstrap.js`、`admin-shell.html`、`modules/admin-view.js` 與 `staging-store-v2.js` 組成。排班、權限、預約、逐筆回診、個管統計、帳號與維護排程各自位於獨立模組。舊 `app.js`、`patient.js` 與 `staging-store.js` 已於 2026-07-21 刪除；歷史基線改由 Git 保存，不再以死碼形式留在會被 Hosting 公開發佈的 `apps/web/public/`。

新版必須保持：草稿排班不影響患者、發布前檢查既有預約、病患取消與櫃台確認分離、回診決定綁定單筆到診、個管統計由指派及完成到診推導，以及管理者權限在狀態轉換層強制執行。

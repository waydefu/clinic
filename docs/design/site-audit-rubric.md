# 公開網站綜合評分標準 v2（2026-10-25）

官網 `/clinic`（含所有子路由）與預約頁 `/booking` 的綜合品質評分。執行步驟見
[`site-audit` 技能](../../.claude/skills/site-audit/SKILL.md)。這是稽核工具，不是
gate：分數不能取代任何必過檢查，也不構成醫療、法律或上線核准。

## 與 v1（2026-10-19）的差別

v1 只存在對話紀錄裡，沒有進 repo，第二次評分時找不到原始標準。v2 保留 v1 的八個
面向與配分，好讓分數能直接比較；改的是「怎麼給分」：

| 問題（v1） | v2 的做法 |
| --- | --- |
| 給分沒有細項，同一頁換人評會差很多 | 每個面向拆成有分數的細項，每項寫明證據來源 |
| 效能是看程式碼推估，沒有實測 | B 項必須用節流後的實測數字（`lab-vitals.mjs`）；CI 的不節流數字只用來抓退步 |
| H 項把 PR 太大、落後 main 算進網站品質 | H 改成「可維護性與驗證」；PR 大小、衝突、落後 main 另列「合併風險」，不計分 |
| 嚴重問題可以被其他細項的高分抵銷 | 加上限規則（見下），例如有禁止的醫療廣告內容時 F 最多 4 分 |
| 視覺分數算法沒記錄 | 視覺分數定義成「程式化評分 50% + VisAWI-S 人工四題 50%」，另列不進總分 |
| 量不到的項目照樣給分 | 量不到就標 `NOT_RUN` 或 `UNAVAILABLE`，該細項不給分，報告寫出原因與覆蓋率 |

## 證據等級

每個細項都要標它的證據：

- **量測**：工具在實際頁面上量到的數字，附指令與日期。
- **靜態**：讀建置產物或原始碼得到的事實，附 `檔案:行號`。
- **判讀**：看截圖或文案後的人工判斷，附截圖或引文。判讀不能冒充量測。

細項對某一頁根本不適用時（例如預約頁沒有醫療文章，F3 不適用）標 `N/A`，該面向改用其餘
細項按比例換算回原本滿分，並寫明換算。`N/A` 只用在頁面本來就沒有這種內容；
有內容但沒量到，是 `NOT_RUN`，記 0 分。

同一份報告裡的量測必須在同一台電腦、同一版本上取得。預覽頻道與本機建置的版本
不同時，要分開寫清楚各項是在哪個版本上量的。

## 分數帶

| 總分 | 意思 |
| --- | --- |
| 90–100 | 達企業級，可上線 |
| 80–89 | 小修後可上線 |
| 70–79 | 需明顯補強 |
| < 70 | 未達企業級 |

## 細項與配分（滿分 100）

### A 搜尋與分享（20）

一律看「不跑 JS 的原始 HTML」（`page-snapshot.mjs`），因為搜尋引擎與社群預覽多半
不執行 JS。預覽頻道刻意帶 `noindex`，這一點不扣分，但要列入上線切換清單。

| 細項 | 分數 | 滿分條件 | 證據 |
| --- | --- | --- | --- |
| A1 每頁獨立的標題、描述、canonical | 6 | 每條路由三者都有，而且互不重複 | 量測 |
| A2 分享預覽 | 3 | og:title、og:description、og:image（絕對網址）齊全 | 量測 |
| A3 原始 HTML 有正文 | 4 | 每頁 `<main>` 有 h1 與主要內容，不是等 JS 填入的空殼 | 量測 |
| A4 結構化資料 | 3 | JSON-LD 能解析，類型正確，名稱、地址、電話與頁面一致 | 量測＋靜態 |
| A5 sitemap、robots 與上線切換清單 | 2 | sitemap 列出所有公開路由；有書面的移除 noindex 步驟 | 靜態 |
| A6 標題階層與圖片替代文字 | 2 | 每頁一個 h1、標題順序正確、內容圖片都有 alt | 量測（CI axe） |

### B 效能（15）

量 `/clinic`、一個療程頁與 `/booking`。官網的 B1～B3 取首頁與療程頁兩頁分數的平均。
單次量測起伏很大（同一頁三次可差兩秒），所以一律取中位數，報告附每次的原始數字。

| 細項 | 分數 | 滿分條件 | 證據 |
| --- | --- | --- | --- |
| B1 節流後 LCP（主畫面出現時間） | 6 | 手機節流中位數 ≤ 2.5 秒；≤ 4 秒得 3 分 | 量測（`lab-vitals.mjs`） |
| B2 版面位移 CLS | 2 | ≤ 0.1；≤ 0.25 得 1 分 | 量測 |
| B3 主執行緒阻塞 TBT | 2 | ≤ 200 毫秒；≤ 600 毫秒得 1 分 | 量測 |
| B4 位元組預算 | 3 | `check:perf` PASS（預算是貼著現況收緊的上限，離上限近不扣分；實際載入快慢由 B1 反映） | 量測 |
| B5 主圖不靠 JS 才被發現 | 2 | 首屏主圖在原始 HTML 裡，或有 `preload` | 量測（`page-snapshot.mjs`） |

### C 無障礙（15）

| 細項 | 分數 | 滿分條件 | 證據 |
| --- | --- | --- | --- |
| C1 自動掃描 | 5 | 同一 commit 的 CI axe 證據（`web-quality-evidence-accessibility`）沒有任何違規 | 量測 |
| C2 焦點框 | 3 | 焦點框對所有背景 ≥ 3:1，且支援 `forced-colors`（Windows 高對比） | 量測＋靜態 |
| C3 觸控目標 | 2 | 互動元件 ≥ 44px（業主要求，比 WCAG 的 24px 嚴） | 量測（`ui-score` 硬性關卡） |
| C4 鍵盤與報讀 | 3 | 只用鍵盤能完成主要流程，狀態變化有報讀 | 量測（e2e）＋判讀 |
| C5 減少動態 | 2 | `prefers-reduced-motion` 時轉場與淡入都停用 | 靜態＋量測 |

**上限：** 有任何 serious 或 critical 等級的 axe 違規，或文字對比不足時，C 最多 9 分。

### D 設計一致性（10）

| 細項 | 分數 | 滿分條件 | 證據 |
| --- | --- | --- | --- |
| D1 token 紀律 | 3 | `check:tokens` PASS，沒有寫死的顏色、間距、字級 | 量測 |
| D2 官網與預約頁是同一個品牌 | 4 | 字體、色彩、按鈕形狀、頁首頁尾一致，切頁不像換了網站 | 判讀（截圖） |
| D3 元件狀態完整 | 3 | 滑過、焦點、停用、載入中、空白、錯誤狀態都有設計 | 判讀 |

### E 轉換與使用流程（10）

| 細項 | 分數 | 滿分條件 | 證據 |

| 細項 | 分數 | 滿分條件 | 證據 |
| --- | --- | --- | --- |

| F2 第 85 條基本資訊 | 3 | 機構名稱、開業執照字號、地址、電話、醫師姓名與證書字號、科別、門診時間 | 靜態 |
| F3 醫療文章可追溯 | 2 | 每篇都有審閱醫師、更新日期、資料來源 | 靜態 |
| F4 預約頁個資告知 | 1 | 有個資告知與同意，自由填寫欄位提醒不要寫病情細節 | 靜態 |

### G 安全與隱私（10）

### H 可維護性與驗證（10）

| 細項 | 分數 | 滿分條件 | 證據 |
| --- | --- | --- | --- |
| H1 CI | 3 | 受評版本的 `Verification evidence` 綠燈 | 量測（CI） |
| H2 行為有測試 | 3 | 使用者看得到的行為（路由、轉場、軟 404、預約步驟）都有 e2e 或單元測試 | 靜態 |
| H3 程式結構 | 2 | 沒有超過約 1,000 行、混了多種責任的前端單檔 | 靜態 |

## 視覺分數（另列，不進總分）

`視覺分數 = 0.5 × 得獎相似度 + 0.5 × VisAWI-S`

- **得獎相似度**：`ui-score` 報告裡的 award-likeness（模型本身已同時用桌機與手機的指標）。必須和對照語料在
  同一台電腦上量，報告要附語料的 AUC 與樣本數。
- **VisAWI-S**：簡潔、多樣、色彩、工藝四題，各 1～7 分，換算成
  `(總和 − 4) ÷ 24 × 100`。由評分者看桌機與手機首屏截圖作答。AI 作答只是代理，
  業主或真人的評分優先。
- `ui-score` 的硬性關卡（對比、觸控目標、動效檢查）不進視覺分數，失敗時回到 C 項扣分。

v1 的視覺分數（官網 73、預約頁 56）沒有留下算法，和 v2 不能直接比較。

## 報告格式

報告寫成 `docs/reviews/YYYY-MM-DD-<主題>-site-audit.md`，並加進
[文件索引](../README.md) 的 Review record。內容依序是：

1. 總分、分數帶、與上一次的差距；
2. 各面向細項分數，每項一句扣分原因與證據；
3. 受評版本、量測日期、各項是在哪個版本或網址上量的；
4. 依嚴重度排序的不足清單；
5. 沒有量到的項目（`NOT_RUN`／`UNAVAILABLE`）與原因；
6. 合併風險。
